# bank-collector

**EN (short):** Read your own bank cabinet in a browser you already logged into. DOM extraction
over CDP: no login automation, no passwords, no SMS codes, no clicks on "download statement",
"pay" or "transfer". There are only two narrow, opt-in write actions: `--enter-code` answers the
cabinet's static "secret code" prompt with a code read from a 0600 file, and a profile may name the
list's own "load more" button (`scroll.load_more_text`) together with its list container
(`scroll.load_more_scope`, required). The button must carry an allowlisted label and live inside the
one container that holds the record's rows; it is pressed only when scrolling added no rows and
exactly one such `<button>` is there, so that the list renders its next page. A same-label control
outside the list is never clicked. Nothing else is clicked. Data stays local (git-ignored `data/`).
Banks are added as YAML profiles; today `alfa` is verified against a live cabinet, including the
load-more click and its scope (verified live on 2026-10-26), `tbank` (operations only, no clicks)
is verified against the live cabinet on 2026-10-27 (expenses checked against the cabinet's day
totals on the days that show one; income not checked numerically), and
`example` is a synthetic profile used by the tests.

---

## Зачем

Российские банки не дают физлицу API: всё, что называется «API банка», — только для юрлиц
(СберБизнес, Альфа-Бизнес, ВТБ, Т-Банк), а открытый банкинг ЦБ для частного клиента ещё не
запущен. Брокерские API (T-Invest, Alor, Finam, BCS, IBKR) есть, но это не банковский счёт.

Поэтому остаётся один честный путь: **прочитать свою же страницу в своём же браузере**, где вы уже
вошли руками. Этот репозиторий делает только это.

## Как работает

1. Вы сами открываете браузер и входите в банк — как обычно, с СМС/passkey/чем угодно.
2. Вы сами запускаете Chrome/Chromium с открытой отладкой:
   `chrome --remote-debugging-port=9222 --user-data-dir=<ваш профиль>`.
3. `bank-collector` подключается по CDP к этому браузеру, ждёт прогрузки кабинета и **читает уже
   отрисованный DOM** по селекторам профиля.
4. Результат — JSON + CSV в `data/` (в git не попадают).

Скрипт почти не нажимает кнопки кабинета: только `goto`, ожидание элемента, чтение текста и
прокрутка уже отрисованного списка. Кликает он ровно в двух узких случаях: необязательный
`--enter-code` отвечает на экран постоянного «Секретного кода» (см. ниже), а кнопка
«Показать ещё» нажимается, только если её полный текст совпадает с `scroll.load_more_text`
профиля, лежит в контейнере `scroll.load_more_scope` (обязателен) и она там ровно одна (она лишь
дописывает строки списка; см. «Прокрутка»). Кнопка с той же подписью вне списка не нажимается.
Оба случая включаются явно — флагом или строкой в профиле — и не трогают никакие другие кнопки.

## Установка и запуск

```bash
pip install -e .
bank-collector --list-profiles
bank-collector --bank alfa --cdp-url http://127.0.0.1:9222           # реальный кабинет Альфы
bank-collector --bank example --cdp-url http://127.0.0.1:9222        # пример (синтетический)
bank-collector --bank alfa --snapshot                                # + обезличенный снапшот страницы

# Браузер за реле Playwriter: адрес с токеном предпочтительно давать через переменную окружения из
# файла 0600, а не в командной строке и не в истории shell (флаг --cdp-url важнее переменной).
# Файл создаётся один раз сразу с правами 0600 (повторный запуск его не обнулит) и заполняется в
# редакторе, не через echo. Значение — в одинарных кавычках: так его одинаково читают и `.`, и systemd.
#   ~/.config/bank-collector/cdp.env:  BANK_COLLECTOR_CDP_URL='ws://<host>:19988/cdp?token=<token>'
#   f=~/.config/bank-collector/cdp.env; install -d -m 700 "${f%/*}"; [ -e "$f" ] || install -m 600 /dev/null "$f"
#   "$EDITOR" ~/.config/bank-collector/cdp.env
# Права этого файла инструмент не проверяет — проверьте сами: ls -l ~/.config/bank-collector/cdp.env
# (должно быть -rw-------).
set -a; . ~/.config/bank-collector/cdp.env; set +a
bank-collector --bank alfa
```

Для systemd то же самое — `EnvironmentFile=%h/.config/bank-collector/cdp.env` в юните. Переменная
убирает токен из argv и истории команд, но не делает его невидимым совсем: окружение процесса видно
тому же пользователю (`/proc/<pid>/environ`, `ps e`).

В сообщениях об ошибке подключения адрес печатается без query-строки, фрагмента и `user:pass@`
(`ws://<host>:19988/cdp?***`), а значения из адреса (от 4 символов, кроме хоста и порта) вычищаются
и из текста ошибки Playwright, так что в лог токен не попадает. Не включайте отладку Playwright
(`DEBUG=pw:*`) в запуске по расписанию: она сама печатает адрес целиком. Заданная, но пустая
`BANK_COLLECTOR_CDP_URL` — ошибка подключения (код 2), а не тихий переход на порт 9222; команды без
браузера (`--list-profiles`, `--import-statement`, `--clear-code-failure`) она не трогает.
`--cdp-url "ws://...?token=..."` по-прежнему работает, но кладёт токен в `ps` и в историю.

Выходные файлы: `data/<bank>.json`, `data/<bank>-balances.csv` и `data/<bank>-transactions.csv`.
Коды возврата: `0` — успех, `2` — браузер недоступен, `3` — профиль невалиден/не найден,
`4` — ничего не извлечено (в отчёте будет `warnings`), `5` — история неполная: прокрутка не
дошла до `stop_before_date` (или упёрлась в `max_rounds`). Код `5` — не успех, даже если отчёт
записан. Если в `data/<bank>.json` уже лежит более длинная история, а новый запуск не доказал
полноту (прокрутка не дошла, `--no-scroll` поверх прокрученного файла или ничего не извлечено),
старый файл не трогается, а новый отчёт пишется в `data/<bank>.partial.json`.

## Поддерживаемые банки

| Профиль | Статус | Что читает | Проверено на живой странице |
|---|---|---|---|
| `example` | verified (синтетика) | остатки, операции | — (фикстура в тестах) |
| `alfa` | **verified, 2026-10-24** | остатки по продуктам с главной, операции с `/history/` | да, живой кабинет в desktop Chrome |
| `tbank` | **verified, 2026-10-27** | операции с `/mybank/operations/` (лента с заголовками дней, виртуализированный список) | да, живой кабинет: 325 операций с 2025-12-31 (от декабря — только 31-е) за ≈3–4 мин (последний прогон 190 с); расходы сверены с итогами дней кабинета: 79 из 86 дней с итогом точно, остальные 7 — ровно на одну операцию, которую банк сам не включает в итог, доход численно не сверялся; без кликов |

Что именно читает `tbank`: на `https://www.tbank.ru/mybank/operations/` — лента операций, где
заголовок дня и операции лежат соседними `<li>` одного `<ul>`; дата берётся у заголовка
(`parse: ru_date`: «27 октября», «Сегодня», «Вчера», год выводится относительно даты запуска).
Дата считается по календарному дню кабинета (`timezone: Europe/Moscow`), а не по UTC.
Список виртуализированный: при прокрутке старые строки исчезают из DOM, а заголовок дня может
уехать раньше своих операций. Операции перед первым заголовком раунда датируются по перекрытию с
предыдущим раундом: самый длинный (не меньше 2 строк, с заголовками) кусок, которым кончается
прошлое окно и начинается текущее, — это одни и те же строки, и весь блок получает дату совпавшей
строки. Совпадение ищется именно «хвост прошлого = начало текущего», а не где угодно в прошлом окне:
повторяющиеся платежи (тот же билет, та же связь в разные дни) иначе получали чужую дату. Кроме
того, найденный день обязан совпасть с тем, что говорят заголовки (день прямо над первым заголовком
текущего окна в прошлом окне, и он новее этого заголовка), а необязательные поля (описание,
кэшбэк) в сравнение не входят — они могут появиться при повторной отрисовке. Если перекрытия нет
или оно не сходится с заголовками (пропущенный или неразобранный заголовок, разрыв между окнами,
случайное совпадение), строки
не датируются, а пропускаются: они попадают в `scroll.headerless_rows`, о них пишется
предупреждение, и запуск помечается неполным (`complete: false`) — вчерашний более полный отчёт
такой прогон не перезапишет.

Что здесь **не** проверено и о чём надо знать:

- Численно сверены только **расходы**, и только по дням, где заголовок показывает итог расходов:
  в прогоне выпускаемого кода (329a7fd) таких дней 86 из 138; на 79 сумма собранных
  отрицательных операций совпала с итогом дня до рубля, на остальных 7 разница — ровно одна
  операция, которую сам банк не включает в итог (5 пополнений брокерского счёта, покупка по QR в
  «Финансах», автоплатёж 200 ₽ в «Другом»); дней, где собрано меньше итога, нет. Доход численно не
  сверялся. Подробности по каждому прогону: `docs/verification/tbank-2026-10-27.md`.
- **Месячные суммы — только по полным месяцам.** Первый месяц файла неполный: прокрутка
  останавливается на `stop_before_date` (`2026-01-01`), поэтому от декабря 2025 в файле только
  31-е число. Последний месяц обрывается датой запуска. Для прогона 2026-10-27 полные месяцы —
  с 2026-01 по 2026-09.
- Строки **не помечены** как «свой перевод». Т-Банк кладёт такие операции в общую категорию
  «Переводы», поэтому правило файла выписки Альфы (категория «Между своими счетами») здесь не
  работает. Наблюдённые 2026-10-27 названия (поле `title`, начало строки, без учёта регистра):
  «Себе в другой банк», «Себе из другого банка», «Пополнение брокерского счета», «Вывод с
  брокерского счета». Список **не исчерпывающий**: переводы между своими счетами внутри Т-Банка
  и другие формулировки в нём не встречались и не проверялись. Для прибыли/убытка такие строки
  надо отфильтровать ниже по течению и периодически просматривать категорию «Переводы» глазами.
- Каждый запуск заново читает всю историю до `stop_before_date` и **перезаписывает** отчёт.
  Для подсчётов берите только `data/tbank.json` и только если в нём `scroll.complete: true`;
  файл `data/tbank.partial.json` (неполный прогон рядом с более полным старым) не суммируйте
  никогда, и никогда не дописывайте в отчёт результаты разных запусков. Первый же неполный
  прогон без старого файла пишется прямо в `data/tbank.json` — отсюда проверка `complete`.
- Две одинаковые операции одного дня остаются двумя строками, только если хотя бы в одном
  проходе они отрисованы вместе (см. ниже).
- Остатков в профиле пока нет, и никаких кликов он не делает: `load_more_text` не задан.

Что именно читает `alfa`: на `web.alfabank.ru/dashboard/` — блоки продуктов с суммой (рекламные
блоки без суммы пропускаются), на `web.alfabank.ru/history/` — операции, сгруппированные по дням
(дата берётся у группы, а не у строки). Это два разных адреса, поэтому профиль описывает страницу
для каждого раздела. Виджет «общий баланс» намеренно не читается: на проверке он не совпал с суммой
карточек продуктов, поэтому в отчёте только то, что видно по каждому продукту, без самодельных
итогов.

«unverified» значит ровно то, что написано: профиль не проверяли на реальном кабинете, и он,
скорее всего, не заработает без правки селекторов. Промежуточного статуса нет: `draft` убран,
профиль либо проверен на живой странице, либо нет. Мы не выдаём непроверенное за рабочее.

## Секретный код кабинета (не СМС)

Альфа после долгого отсутствия показывает экран **«Секретный код»** — это постоянный код
кабинета, который вы знаете, а не СМС и не одноразовый пароль. Его можно не вводить руками:

```bash
mkdir -p ~/.config/bank-collector && chmod 700 ~/.config/bank-collector
printf '%s\n' 'ВАШ-КОД' > ~/.config/bank-collector/alfa-code
chmod 600 ~/.config/bank-collector/alfa-code

bank-collector --bank alfa --cdp-url ... --enter-code
```

Что важно знать:

- `--enter-code` **выключен по умолчанию**: без флага инструмент ничего не печатает в кабинет.
- Код читается только из файла (путь из профиля `unlock.code_file` или `--code-file`) либо из
  переменной `BANK_COLLECTOR_CODE`. В командной строке код не передаётся — иначе он попадёт в
  историю и в `ps`.
- Файл должен быть `0600`: файл, читаемый группой или всеми, инструмент откажется использовать
  (код выхода 3) и подскажет `chmod 600`.
- Код никогда не пишется в логи, отчёты, JSON и сообщения об ошибках — везде `***`.
- За один запуск вводится **не больше одного кода**. Если экран пишет «Осталось N попыток» и
  N меньше `min_attempts_left` (по умолчанию 3), инструмент не вводит ничего: лучше разовый
  ручной вход, чем блокировка кабинета.
- Печатается ровно одна строка: `UNLOCK: экран «Секретный код» — код введён` или
  `UNLOCK: не удалось (<причина>)`. Если экрана нет — тишина, обычная работа.
- **Маркер неудачной попытки**: если ввод кода не привёл к кабинету, рядом с файлом кода
  появляется `alfa-code.failed` — текстовый файл с отметкой времени и причиной, кода в нём нет.
- **Где он лежит**: в том же каталоге, что и файл кода, права `0600`; по умолчанию это
  `~/.config/bank-collector/alfa-code.failed`.
- **Ежедневный запуск после неудачи больше не вводит код**, пока маркер не снимёте руками:
  `bank-collector --clear-code-failure` (или `rm ~/.config/bank-collector/alfa-code.failed`).
  Флаг работает без браузера и ничего не вводит.
- **Зачем это**: живой экран Альфы не всегда показывает, сколько попыток осталось («Осталось N
  попыток» бывает только после неудачной попытки) — без маркера устаревший код в файле тихо
  блокировал бы кабинет за несколько дней.
- Экран живёт на `private.auth.alfabank.ru/passport/cerberus-mini/dashboard/pincode`; селекторы
  профиля сняты с него 24.10.2026, но сквозной ввод кода намеренно не проверялся (на экране
  оставалось 2 попытки) — считайте это «проверено по разметке, не по результату».

`--enter-code` — единственное место, где скрипт вводит данные (`fill`). `click` есть только в
`bank_collector/unlock.py` (кнопка «Вперёд» на экране кода) и в одном узком месте
`bank_collector/collect.py` — кнопка «Показать ещё» (см. «Прокрутка»); всё остальное — чтение.

## Импорт выписки

Кабинет показывает не всю историю. Если нужны операции за более давний период, выгрузите выписку
руками: в кабинете Альфы — «Выписки и справки» → выписка по счёту/карте → период, **все счета**,
формат **CSV**. Затем импортируйте файл — браузер для этого не нужен:

```bash
bank-collector --bank alfa --import-statement ~/Downloads/statement.csv --out data
```

Что происходит:

- файл читается **только локально** (UTF-8 с BOM, разделитель — запятая); браузер, CDP и сеть не
  используются, ничего никуда не отправляется;
- отчёт пишется в `data/alfa-statement.json` — **никогда** не в `data/alfa.json`, чтобы импорт не
  перепутался с обычным запуском по кабинету;
- с `--format csv` или `--format both` (по умолчанию) дополнительно пишется
  `data/alfa-statement-transactions.csv` — те же операции для таблиц; `--format json` пишет только
  JSON. Флаги `--json`/`--csv` (вывод в stdout) с импортом несовместимы и отклоняются;
- печатаются строки `written: <путь>` для каждого файла и сводка
  `statement: N operations, <дата> .. <дата>`;
- коды возврата: `0` — успех, `3` — неизвестный банк, нечитаемый файл, не UTF-8 CSV (cp1251, PDF или
  Excel, переименованный в `.csv`), файл без шапки выписки (сохранённая HTML-страница вроде
  `<html><body>Сессия истекла</body></html>`, пустой или однострочный мусор — сообщение
  `not a bank statement export`), нет обязательных колонок или ни одна строка не разобралась,
  `4` — пустая выписка: **только** литерал `operationList` или шапка банка без единой строки
  (в кабинете нужно выбрать все счета и выгрузить снова);
- `--enter-code` и `--cdp-url` с импортом несовместимы и отклоняются.

Что попадает в отчёт: дата операции и дата транзакции (ISO `YYYY-MM-DD` и исходная строка), название
(мерчант, иначе комментарий, иначе тип), категория, тип, статус, комментарий, MCC, **название** карты,
название счёта (неразрывный пробел заменяется обычным), **последние 4 цифры** номера счёта и сумма
со знаком: `Списание` — минус, `Пополнение` — плюс; `RUR` показывается как `RUB`.

Статусы: импортируются строки с пустым статусом (так экспорт помечает поступления) и со статусом
`Выполнен` (завершённые списания). Строка с другим статусом (`Отклонён`, `В обработке`) пропускается
с одним предупреждением на каждый различный статус: `N rows with status 'X' skipped`. Строка с битой
**датой операции** или суммой пропускается с предупреждением, где указаны только номер строки и
колонка; если строки есть, но ни одна не разобралась, команда завершается кодом `3` с сообщением
`none of the N rows could be read` и первыми предупреждениями по строкам.

Обязательна только дата операции. Если `transactionDate` пуста, `transaction_date.value` будет
`null` без предупреждения; если она заполнена, но не разбирается, строка **остаётся** в отчёте с
`transaction_date.value: null` и одним предупреждением
`line N: cannot parse transactionDate, kept with an empty value` — сама операция уже состоялась, и
терять её из-за даты проводки нельзя.

Длинные номера маскируются: заменяются на `***` плюс последние 4 цифры — и в текстовых полях
(название/мерчант, комментарий, категория, счёт, карта, даты), и в имени сохранённого файла
(`statement.file`, `source_url`), и в **каждом предупреждении и сообщении об ошибке**, включая путь
нечитаемого файла. Маскируется:

- любой ряд из 12 и более цифр; между цифрами допускаются пробел, неразрывный пробел, `-`, `–`,
  `—`, `.`, `/`, `*`, но не больше двух разделителей подряд (поэтому обычный текст и даты не
  задеваются: `1250.50 руб 12.10.2026` остаётся как есть), — так ловятся и `40817.810.1.00001234567`,
  и `4081–7810–0000–0000–0099`, и номер, к которому прилип `*`;
- уже маскированный номер карты вида `220015******1234` (6 цифр, 4 и более `*`, 4 цифры), в том
  числе `220015******1234*`.

Переводы между своими счетами не выбрасываются, но и не угадываются по совпадению даты и суммы.
Строка помечается как перевод между своими счетами (`own_transfer: true`) **только когда так говорит
банк**:

- категория строки — `Между своими счетами` (регистр и неразрывные пробелы не важны) — тогда
  `own_transfer_reason: "category"`;
- либо название начинается с `Перевод себе` — так банк пишет перевод на свой счёт в другом банке
  («Перевод себе в другой банк через СБП»), категория там общая `Переводы` — тогда
  `own_transfer_reason: "title"`.

У остальных строк `own_transfer: false` и `own_transfer_reason: ""`.

Дополнительно помеченные строки связываются в пары **внутри одной выписки**: одна валюта, одна дата
операции, равная абсолютная сумма, противоположные типы (`Списание`/`Пополнение`) и разные номера
счетов; связывание жадное, по порядку строк в файле, каждая строка участвует не более чем в одной
паре. Обе строки пары получают короткий `own_transfer_pair` (`"p1"`, `"p2"`, …), у остальных там
`""`. Пара ищется только среди уже помеченных строк: аренда `-50000` с одного счёта и зарплата
`+50000` на другой в один день парой **не** считаются. В блоке `statement` два счётчика:
`own_transfers` — сколько строк помечено, `own_transfer_pairs` — сколько пар найдено. Перевод в
другой валюте (например, между своими счетами в USD) с категорией-сигналом помечается и без пары.
**Исключайте помеченные строки из итогов доходов и расходов**, иначе перевод между своими счетами
посчитается и доходом, и расходом.

Чего в отчёте **нет**: полного номера счёта, номера карты и бонусных значений — они не читаются и не
сохраняются.

### Выписка и ежедневный отчёт

`data/alfa-statement.json` — **бэкфилл истории** за те месяцы, которые покрывает выгруженная выписка.
Ежедневный `data/alfa.json` — свежее окно кабинета (последние операции, которые он отрисовал). Они
**перекрываются**: при объединении дедуплицируйте строки по `(date, amount, title)` — по дате, сумме
и названию, — потому что одна и та же операция попадёт в оба файла. Для месяцев, которые покрывает
выписка, источник истины — выписка: она полнее дневного окна и не зависит от того, как далеко
прокрутился кабинет.

В дневном `data/alfa.json` у каждой операции тоже есть поле `category` (профиль его читает); в JSON
это `transaction.category.value`, а название — `transaction.title.value`. Пометки `own_transfer` там
**нет**: разметка дневного файла в этот выпуск не входит. Потребитель отчёта должен сам применить к
дневному файлу то же правило, что описано выше: `category.value` (без учёта регистра и неразрывных
пробелов) равна «Между своими счетами» **или** `title.value` начинается с «Перевод себе» — такую
строку нужно исключить из итогов доходов и расходов. Пары внутри дневного окна не строятся: оно
неполное, пара может оказаться за его границей.

### Схема отчёта и `schema_version`

`schema_version` отчёта — `"2"`. Версия 2 только **добавляет необязательные ключи** к версии 1,
поэтому всё, что читало версию 1, продолжает работать:

- блок `statement` (только у импорта выписки): `file`, `rows`, `period`, `accounts`,
  `own_transfers`, `own_transfer_pairs`;
- у строки выписки — `own_transfer` (boolean), `own_transfer_reason` (`"category"`, `"title"` или
  `""`) и `own_transfer_pair` (`"p1"`, `"p2"`, … или `""`).

Схема одной операции — `schema/transactions.schema.json`: перечисленные выше поля объявлены в ней
явно (`account_last4`, `title`, `category`, `type`, `status`, `comment`, `mcc`, `card`, `account`,
`transaction_date` — как обычные поля-листья, три own-поля — как скаляры), поэтому строка выписки
проходит валидацию. Остальные ключи, как и раньше, должны быть полем-листом
(`raw`/`value`/`currency`/`money`) — это правило `additionalProperties` в схеме.

## Ограничения и риски (читать до запуска)

- **Прокрутка — тоже чтение.** Чтобы догрузить историю, скрипт прокручивает уже
  отрисованный список и снова читает DOM: сама прокрутка ничего не нажимает, запросы свои не
  отправляются, кнопка «Скачать выписку» не трогается. Альфа отдаёт по 20 операций за раз, поэтому
  без прокрутки в отчёт попали бы только 20 самых свежих операций, а с прокруткой — весь год до
  `2026-01-01`.
- **Одна кнопка «Показать ещё».** Она включается только парой ключей: `scroll.load_more_text`
  (сам текст) и `scroll.load_more_scope` (CSS-селектор контейнера списка). Без скоупа профиль
  отклоняется; скоуп без текста — тоже. Если прокрутка не добавила ни одной новой строки,
  драйвер оставляет только контейнеры скоупа, которые содержат хоть одну строку этой записи;
  их должно быть **ровно один**, иначе клика нет, в `warnings` пишется `load-more scope '…'
  matched N list containers, none clicked`, прокрутка останавливается с `stop: error` (код `5`).
  Кнопка ищется **только внутри этого контейнера**, среди `<button>`, и её **весь** текст (без
  крайних пробелов, внутренние пробелы схлопнуты) должен **в точности** совпадать со строкой —
  не «содержать» её. Текст обязан входить в белый список: **только** «Показать ещё» и его
  орфографический вариант «Показать еще» (регистр не важен); «Скачать выписку», «Оплатить»,
  «Загрузить ещё» и любая другая строка — ошибка профиля. Регистр не важен и при сверке с
  кнопкой: профиль может написать «показать ЕЩЁ», в отчёт и в сравнение попадёт каноническое
  «Показать ещё». Нажимается кнопка,
  только если она в контейнере **ровно одна**; клик лишь просит список дописать следующую
  порцию строк. Две и больше — клика нет, предупреждение `N buttons named '…', none clicked`,
  `stop: error` (код `5`); ноль — обычный пустой раунд. Кнопка с той же подписью **вне** списка
  (блок офферов) или не `<button>` (ссылка, `[role=button]`, а также `div`/`span` с тем же
  текстом) не нажимается никогда; если
  прокрутка закончилась пустым раундом, а такая кнопка на странице есть, пишется предупреждение
  «… found outside the list or not as a button (N), not clicked — history may be incomplete» и
  `complete` принудительно становится `false` (код `5`), чтобы не перезаписать более полный
  снапшот. `scroll.max_clicks` (по умолчанию 100) ограничивает число таких кликов; каждый клик
  считается раундом и расходует `scroll.max_rounds`. Другие кнопки («Скачать выписку»,
  «Оплатить», «Перевести») не нажимаются никогда, страницы перечисления не переключаются.
  **Клик и скоуп проверены на живом кабинете 26.10.2026**: один клик дописал 40 операций назад
  до 2025-11-01, прокрутка остановилась по `stop: date`, запуск вернул `complete: true`.
- **Как отключить прокрутку**: флаг `--no-scroll` (только первый экран, как раньше) или убрать
  блок `scroll:` из профиля банка. Настройки прокрутки — в профиле: `scroll.max_rounds` (шагов,
  по умолчанию 50), `scroll.step_px` (пикселей за шаг, 1500), `scroll.settle_ms` (пауза после
  шага, 800), `scroll.stop_after_empty_rounds` (стоп после стольких пустых шагов, 3),
  `scroll.stop_before_date` (YYYY-MM-DD: стоп, как только встретилась дата раньше этой — сам этот
  день собирается целиком), `scroll.load_more_text` (необязательный полный текст кнопки догрузки,
  по умолчанию выключено), `scroll.load_more_scope` (обязательный селектор контейнера списка, если
  текст задан) и `scroll.max_clicks` (потолок кликов по ней, 100).
- **Неполная история не выдаётся за полную**: если список перестал расти раньше
  `stop_before_date`, в `warnings` будет «history reaches back only to …», а в блоке `scroll`
  отчёта — `oldest_date`, самая старая собранная дата, `clicks`, сколько раз нажималась кнопка
  догрузки, и `complete: true|false`; запуск с неполной историей завершается кодом `5`. Две
  одинаковые операции за один день (два кофе по 250 ₽) остаются двумя строками, только если хотя
  бы в одном проходе они отрисованы вместе; виртуализированный список, который показывает их по
  одной, сольёт вторую с первой — известное ограничение.
- **Селекторы ломаются** при любом редизайне кабинета; это обслуживание, а не «поставил и забыл».
- **Сессия истекает** (обычно недели–месяцы): либо один раз вручную войти снова, либо положить
  постоянный код кабинета в файл и запускать с `--enter-code` (см. раздел ниже).
- **Антифрод**: банк может отреагировать на необычную автоматизацию; автоматизацию входа мы не
  делаем именно поэтому.
- **ToS**: у банков есть запрет на автоматизированный доступ; риск блокировки — на вас.
- **Скачивание выписок не автоматизируем**: кнопка «скачать» часто требует push-подтверждения,
  а DOM-таблица с операциями есть и так.
- Данные лежат только локально в `data/`; удалить — `rm -rf data/`.
