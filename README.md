# bank-collector

**EN (short):** Read your own bank cabinet in a browser you already logged into. Read-only DOM
extraction over CDP: no login automation, no passwords, no SMS codes, no clicks on "download
statement", "pay" or "transfer". Data stays local (git-ignored `data/`). Banks are added as YAML
profiles; today `example` is a tested synthetic profile and `alfa` is an unverified placeholder.

---

## Зачем

Российские банки не дают физлицу API: всё, что называется «API банка», — только для юрлиц
(СберБизнес, Альфа-Бизнес, ВТБ, Т-Банк), а открытый банкинг ЦБ для частного клиента ещё не
запущен. Брокерские API (T-Invest, Alor, Finam, BCS, IBKR) есть, но это не банковский счёт.

Поэтому остаётся один честный путь: **прочитать свою же страницу в своём же браузере**, где вы уже
вошли руками. Этот репозиторий делает только это.

## Как работает

1. Вы сами открываете браузер и входите в банк — как обычно, с СМС/passkey/чем угодно.
2. Вы сами запускаете Chrome/Chromium с открытой отладкой:
   `chrome --remote-debugging-port=9222 --user-data-dir=<ваш профиль>`.
3. `bank-collector` подключается по CDP к этому браузеру, ждёт прогрузки кабинета и **читает уже
   отрисованный DOM** по селекторам профиля.
4. Результат — JSON + CSV в `data/` (в git не попадают).

Скрипт никогда не нажимает кнопки. В коде нет ни одного `click`/`fill`/`submit` — только
`goto`, ожидание элемента и чтение текста.

## Установка и запуск

```bash
pip install -e .
bank-collector --list-profiles
bank-collector --bank example --cdp-url http://127.0.0.1:9222        # пример (синтетический)
bank-collector --bank example --snapshot                              # + обезличенный снапшот страницы
```

Выходные файлы: `data/<bank>-<дата>.json` и `.csv`. Коды возврата: `0` — успех, `2` — браузер
недоступен, `3` — профиль невалиден/не найден, `4` — ничего не извлечено (в отчёте будет `warnings`).

## Поддерживаемые банки

| Профиль | Статус | Что читает | Проверено на живой странице |
|---|---|---|---|
| `example` | verified (синтетика) | остатки, операции | — (фикстура в тестах) |
| `alfa` | **unverified** | остатки, операции | **нет**, селекторы — заглушки `TODO-*` |

«unverified» значит ровно то, что написано: профиль не проверяли на реальном кабинете, и он,
скорее всего, не заработает без правки селекторов. Мы не выдаём непроверенное за рабочее.

## Ограничения и риски (читать до запуска)

- **Селекторы ломаются** при любом редизайне кабинета; это обслуживание, а не «поставил и забыл».
- **Сессия истекает** (обычно недели–месяцы): нужно один раз вручную войти снова.
- **Антифрод**: банк может отреагировать на необычную автоматизацию; автоматизацию входа мы не
  делаем именно поэтому.
- **ToS**: у банков есть запрет на автоматизированный доступ; риск блокировки — на вас.
- **Скачивание выписок не автоматизируем**: кнопка «скачать» часто требует push-подтверждения,
  а DOM-таблица с операциями есть и так.
- Данные лежат только локально в `data/`; удалить — `rm -rf data/`.

## Добавить свой банк

`docs/ADD_A_BANK.md`: обезличенный снапшот страницы → селекторы → профиль YAML → фикстура и тест.
Ничего, кроме YAML-профиля, для нового банка обычно не нужно.

## Безопасность

`docs/SECURITY.md`: модель угроз, что скрипт не делает, где лежат данные, что делать при утечке.
