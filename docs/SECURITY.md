# Безопасность и границы

Этот документ описывает, что инструмент делает, чего он не делает и какие риски остаются на
пользователе. Если что-то здесь расходится с кодом — прав код, и это баг в документе.

## Что скрипт НЕ делает

- **Не логинится.** Нет полей для логина, пароля, СМС-кода, passkey. Нет отправки форм.
- **Не хранит и не передаёт секреты.** Ни куки, ни токены, ни пароли не читаются и не пишутся.
  Постоянный код кабинета (только при `--enter-code`) лежит в файле `0600` вне репозитория,
  читается один раз за запуск, не попадает в argv, логи, отчёты и тексты ошибок (маскируется как
  `***`); файл с правами шире `0600` отвергается.
- **Почти ничего не нажимает.** Обычный запуск — только переход по URL, ожидание элемента,
  чтение текста/атрибутов и прокрутка уже отрисованного списка. Прокрутка — это тоже чтение:
  она двигает вьюпорт, ничего не кликает, ничего не меняет в DOM и не отправляет запросов от
  себя (нужен только чтобы догрузить строки, которые кабинет сам добавляет при прокрутке).
  Ровно одно исключение: `--enter-code` (по умолчанию выключен) вводит
  постоянный «Секретный код» кабинета в распознанный экран и нажимает на нём «Вперёд». Всё это
  живёт в одном модуле `bank_collector/unlock.py`, и это единственные `fill`/`click` в проекте.
- **Не скачивает выписки.** Кнопка «скачать»/«экспорт» часто требует push-подтверждения и меняет
  состояние счёта — мы её не трогаем.
- **Не платит, не переводит, не оформляет.** Ни одной мутирующей операции.
- **Не ходит в сеть сам.** Единственный сетевой вызов — локальный CDP-эндпоинт браузера.
- **Не отправляет данные в облако.** Никакой телеметрии, никаких «синхронизаций».

## Вкладки и токен реле

- Инструмент открывает **свою** вкладку и закрывает её в конце. Вкладки, которые у вас уже открыты,
  он не навигирует: ваша сессия в кабинете и открытые страницы остаются как были.
- Вариант `--cdp-url "ws://<host>:19988/cdp?token=<token>"` (реле Playwriter) удобен, но токен
  попадает в историю команд и в `ps`. Токен реле — такой же секрет, как пароль от кабинета: не
  вставляйте его в скрипты и в переписку, а если он засветился — перевыпустите.

## Модель угроз

| Угроза | Что делаем |
|---|---|
| Кража учётных данных инструментом | Инструмент их не запрашивает и не видит: вход уже сделан вами в вашем браузере |
| Утечка собранных данных | Данные только в `data/` (git-ignored), формат — JSON/CSV на вашей машине |
| Случайный коммит данных в git | `.gitignore` исключает `data/`, `snapshots/`, `*.csv`; перед коммитом проверяйте `git status` |
| Подмена профиля (чужие селекторы тянут лишнее) | Профиль — обычный YAML в репозитории: читайте его перед запуском, он короткий |
| Автоматизация входа и блокировка счёта | Логин/СМС/passkey — только ручные; скрипт подключается к уже открытой сессии. Постоянный код кабинета вводится только по флагу, один раз за запуск и не вводится, если на экране мало попыток |
| Блокировка кабинета из-за неверного кода в файле | Неудачный ввод оставляет рядом с файлом кода маркер (`.failed`): следующий запуск ничего не вводит, пока маркер не снимёте руками (`--clear-code-failure`) — живёт экран или нет, код сам не повторяется |
| Утечка постоянного кода кабинета | Код хранится в файле `0600` вне репозитория, не логируется и не передаётся в argv; при подозрении на утечку — сменить код в кабинете |
| Антифрод-реакция банка на автоматизацию | Риск остаётся: не запускайте по расписанию чаще, чем вам реально нужны данные, и не гоняйте по 20 банкам сразу |

## Где лежат данные

- `data/<bank>.json` — остатки и операции, схема в `schema/`.
- `data/<bank>-balances.csv`, `data/<bank>-transactions.csv` — те же данные для таблиц.
- `snapshots/` — обезличенные HTML/текст страницы (только при `--snapshot`), нужны для написания
  селекторов: вырезаются скрипты, значения полей ввода, e-mail и длинные цифровые
  последовательности.

Удалить всё: `rm -rf data/ snapshots/`.

## Что делать при утечке

1. Удалить `data/` и `snapshots/`.
2. Сменить пароль в банке и завершить все сессии в кабинете.
3. Проверить, не попал ли файл в git: `git log --all --stat | grep -i data/`.
4. Если данные ушли в публичный репозиторий — считать их скомпрометированными, а не «удалёнными».

## Правовая рамка

У банков есть правила использования кабинета, которые могут запрещать автоматизированный доступ.
Инструмент не обходит защиту и не подделывает действия пользователя, но **риск претензий и
ограничений по счёту лежит на том, кто запускает**. Если банк требует подтверждения для просмотра
данных — это сигнал остановиться, а не обходить.
